The problem

AI coding tools assume the cloud.
Many teams can't use the cloud.

🔒

Code can't leave

Banks, government, defense, telecom and regulated industries run on air-gapped or restricted networks. Source code must stay inside.

🧠

Local models are small

Self-hosted 7B–32B models usually have 8K–32K of context — a fraction of what cloud agents are designed for.

🧩

And they're sloppy

Open models write tool calls as text, leak markup, stop mid-task, announce work they never do, and loop. Agents built for frontier models fall apart.

Dcode is built from the ground up for exactly this environment.

Meet Dcode

One binary. Your model. Your network.

Ask in plain language — "fix the failing test", "add a health endpoint", "explain this repo". Dcode reads your code, edits files, runs commands and checks git, showing every step and asking before anything risky.

Built for small context windows

Every token of a 32K window counts

  • Read only what's needed — numbered line ranges, regex search, depth-limited listing.
  • Edit, don't rewrite — exact-match edit_file instead of re-sending whole files.
  • Output caps scale with the window — about 12% per tool result; long command output keeps head and tail.
  • Helpers explore elsewhere — only a short report returns to the main conversation.
  • Index, don't inline — skills and memories appear as one-liners; full text loads on demand.
  • Automatic compaction at ~75%: trim old tool output first, then summarize older turns.

Robust with real open models

Small models make mistakes. Dcode absorbs them.

🔁 Follow-through

"Building the artifact now." — and it stops? Dcode reminds the model to actually do it (capped, never loops).

🧾 Text tool calls

Recovers calls written as <tool_call> or fenced JSON when the server doesn't parse them.

🧹 Leaked markup

Cleans tags models leak into tool names (e.g. DeepSeek ｜DSML｜) and salvages arguments.

💭 Hidden reasoning

Strips <think> blocks so reasoning never refills the context.

✂️ Cut-off replies

Hits the output limit? Dcode asks it to continue; big artifacts can be built in parts.

🛡️ Guard rails

Refuses empty writes that would erase a file, breaks repeated-call loops, nudges silent stops, caps re-saves.

It learns server quirks too — which optional parameters a backend rejects — and stops sending them.

Multi-agent

Helpers do the legwork — in their own context

🧭 Explorer

Finds and reads code; reports facts with file:line references. Read-only.

💻 Coder

Makes one well-defined change with minimal edits.

👁 Reviewer

Reviews code or a diff for real bugs and security issues. Read-only.

🧪 Tester

Writes and runs focused tests; reports pass/fail.

Read-only helpers run in parallel. Only a capped report reaches the main conversation — exploration that would burn 20K tokens costs ~500.

You stay in control

Four modes — Shift+Tab to switch

Accept edits

Default. Edits files freely; asks before commands, deletions and commits.

Auto

Never asks. For trusted, sandboxed projects only.

Plan

Read-only. Investigates and writes a plan, then asks "Ready to implement this plan?"

Manual

Asks before every edit (with a diff preview) and every command.

Approvals, your way

Allow · Allow for this session · Deny — from the terminal menu (y a n) or a card in the web UI. Whichever answers first wins; the menu then shrinks to a single line.

Undo anything Dcode changed

Every task saves a checkpoint. /undo restores the files — even outside git — and tells the model it was undone.

The terminal

Keyboard-first, calm, and informative

  • Input pinned to the bottom with a labeled ── ❯ dcode ── ◆ mode ── rule
  • White text; blue only for structure — answers get a blue gutter
  • / suggestions below the input · Ctrl+O expands output
  • Every task ends with a report: files changed, commands run
  • Inline red/green diffs for edits
  • Ctrl+C stops a task · twice exits

Memory & skills

It remembers your project — and follows your playbooks

🧠 Three layers of memory

Working — the live chat, compacted. Episodic — summaries of past sessions. Semantic — saved facts per project or global. Plain Markdown, searched offline (BM25), recalled automatically.

⚡ Skills

Nine built in: devops, developer, ui-designer, code-reviewer, artifact-creator, tester, security-auditor, docs-writer, debugger. Dcode picks the right one; pin favorites. Create your own by asking Dcode, in the UI, or with a .md file — shareable per project via git.

Everyday workflow

Git-aware, and honest about what it did

/diff · /commit

See uncommitted changes in color; commit with a message Dcode writes from the diff — after you confirm.

/undo

Roll back the files Dcode changed in the last task, git or not.

/compact

Summarize a long session into a short memory and free the context window.

⚙ Background jobs

Servers and watchers run in the background; /jobs shows output or stops them.

📋 Task reports

Every task ends with what changed, which commands ran, and what's left.

🏷️ Named chats

Chats are titled from your first message; /resume or the web UI brings them back.

Workspace sandbox

Approvals

Commands, deletions and commits ask first; empty writes that would erase files are refused.

Private web UI

127.0.0.1 only, per-user secret token, CSRF and DNS-rebinding protection. Other users on a shared server can't see your sessions.

Sandboxed artifacts

Secrets

↩️

Reversible

Checkpoints for every task; nothing is pushed or committed without you.

Deploy

From build machine to air-gapped server in four steps

Build

On a connected machine with the same OS/CPU:

make deb

Copy

USB or internal mirror:

dcode_0.3.1_amd64.deb
install-airgap.sh

Install

No internet, no pip:

sudo ./install-airgap.sh \
  dcode_0.3.1_amd64.deb

Point & run

At your local model:

export DCODE_BASE_URL=\
  http://gpu:8000/v1
export DCODE_MODEL=\
  qwen2.5-coder
dcode

Configuration lives in ~/.dcode/config.json or environment variables (env wins — handy for shared servers). Old CODE_ONE_* settings still work.
