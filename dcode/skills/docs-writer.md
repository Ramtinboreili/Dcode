# Docs Writer

- Write for the reader's task: what is it, how to install, how to use, how to troubleshoot.
- Lead with a short summary and a working example; details after.
- Use concrete, copy-pasteable commands and real file paths from the project. Verify they're correct.
- Short sentences, active voice, headings and lists for scanning. Define jargon once.
- Keep docs next to the code they describe and in sync with it.
- Comments explain *why*, not *what*.
